# 毎回のラダー画像提示

ユーザー指定：ラダーの分析・対策案・修正結果を説明する回答では、今回の論点に対応した**ラダー画像を毎回本文に埋め込む**。ASCII図や文字の論理式だけで代替しない。図不要の明示指示は優先。スキル保守や保存先の連絡だけの回答に無関係な回路を足す必要はない。

## 見た目：添付された2段ラダー図が基準

表示見本は[assets/ladder-style-reference.png](../assets/ladder-style-reference.png)。再描画できるJSONも同梱している。

- 白背景、黒に近い線と文字。接点・コイル・左右母線・自己保持の並列枝を大きく描く。
- **青は今回の変更箇所・比較の要点**。すべてを青にせず、未変更部分は黒。
- NO／NCは実際の記号で区別。SET／RESETコイルはS／Rを明示。AND／ORや、分岐する位置・合流する位置を正確に描く。
- タイマー・立上り・MOVEなどは四角いブロック。複数条件を要約ブロックにする場合は「○○条件の要約」「開始条件のみ抜粋」と明記し、実接点をすべて描いた図と混同させない。
- タイトルは何の問題／何の対策かを短く。対象版、セッション、行番号、軸名を副題へ。
- 「現状」と「対策案」を上下または別画像で比較。大きな図を縮小せず、1枚1論点、複数の問題は必要枚数へ分割。
- 略称は図の下に実変数名を対応させる。例：`M1＝RCON2_2_M[1]`、`Done＝RCON2_2_MoveDone`。同じM表記を別配列の意味で混ぜない。
- 補足は1文1行、回路と間隔を空ける。タイトル30～36px、ラベル22～26px程度、全辺1800px以下を標準にする。
- 最後に`提案・未反映`／`反映済み`、検証範囲、必要な前提を短く付ける。描いたことを実装済みや実機検証済みと扱わない。

## 作成・提示

`scripts/render_ladder.py`は図用JSONをPNGへ変換する。Pillowを使用。実プロジェクトへは書き込まない。

```powershell
python -X utf8 scripts/render_ladder.py --input assets/ladder-example.json --output C:/work/ladder-example.png
```

スキーマは見本JSONがそのまま使用例。`elements`の順に描き、wire／contact／coil／block／textを明示配置する。

| 要素 | 主な指定 |
|---|---|
| wire | `points: [[x,y], ...]`。縦線・横線・分岐を明示 |
| contact | `x,y,width,label,nc`。yは回路の中心線 |
| coil | `x,y,width,label,mode`。modeはnormal/set/reset |
| block | `x,y,width,height,label`。yは中心線 |
| text | `x,y,text,size,width,align`。width内で折り返す |
| 共通 | `color: "ink"`または`"change"`で黒／青 |

描画後は画像を必ず開いて、接点・枝・合流・略称・行番号・文字切れ・重なりを確認する。JSONの座標はレイアウトだけであり、制御の正しさを自動判定しない。

回答では`![ラダーの説明](絶対パスのPNG)`を使用し、画像を表示する。ファイルリンクだけで終わらせない。本文に「どの接点を、なぜ替えるか」を短く添える。

## 図の内容の照合

- 現状図は今回読み直した保存データを根拠にする。旧画像の配線を根拠なく転用しない。
- 開始工程と実完了信号を区別し、自己保持枝が何を迂回するか、解除接点がどの枝に共通かを確かめる。
- 簡略図で省略した条件は注記する。運転許可・非常停止・Retry等を省略した図を、そのまま置換可能な完全ラダーとして提示しない。
- 参照図の見た目を再利用しても、そこにあるPEND／タイマーや回路方式を今回のプログラムへ勝手に採用しない。
