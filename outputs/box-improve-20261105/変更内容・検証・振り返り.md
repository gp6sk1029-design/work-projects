## 改善内容

### 1．重複した通常コイルを分離

RCON2_5_Autoの用途を次のように分離した。番号は移動位置番号ではなく要求元の識別番号。

|旧Dの箱詰め行|移動用途|Eの要求番号|
|---:|---|---|
|3|初回コンテナ設置|[1]|
|5|初回の方向NG排出|[4]|
|8|コンテナ受渡可能位置|[2]|
|11|通常のコンテナ設置|[5]|
|37|満杯コンテナ排出位置|[6]|
|40|排出後の受渡可能位置|[3]|

RCON2_5受け側に[1]～[6]を接続。
Z軸の受け側には[4]・[5]を含め[1]～[5]を接続。
シリンダーにも同名通常コイル重複があったため、コンテナ排出戻をAuto[1]～[3]、排出行をAuto[1]～[2]へ分離。
Outputではコンテナ排出戻とチャック戻の動作・異常監視に不足接点を追加した。排出行のAuto[2]は既に受け側にあり、その回路は保持。
Output変更行は280・282・286・288。既存の自動/手動、一時停止、M9999、リセットタイマー条件を保持。

### 2．RCON2のX・Y・Z・コンテナ軸の数値転送を接続

既存の位置、位置決め幅、速度、加減速設定を構造体へ転送する4行のP_OffをP_Onへ変更。
これらは数値転送だけで、Startの許可ではない。
現在位置・電流・速度・アラーム・DataValidの監視値転送は、該当軸のDataValidが有効な時だけ行う。
押付け、ジョグ、原点復帰、ブレーキ等の依頼外の未接続テンプレートは有効化していない。
RCON1と段バラシ用RCON2_1の回路は保持。

### 3．開始・受付・完了を整合

既存の立上り、自己保持、TON、配列変数を利用したが、受付管理は今回補強した処理。正常運転確認済み回路をそのまま転用したものではない。

1. 要求ごとにUpを取り、要求OR全体が切れない番号切替でも新しい立上りを検出する。
2. 運転許可中だけ要求を保留・受け付ける。前回のMoveDone保持中に来た要求は保持終了まで保留する。
3. Start出力を20ms以上保持し、PEND（IN_PositionDone）のOFFを今回指令の受付として記憶する。
4. 受付後にStartをOFFにし、次のPEND ONを完了とする。最初からONの旧PENDだけで完了しない。
5. MoveDoneの既存100ms保持を維持する。
6. 許可喪失時は開始状態・受付保留を破棄。RESET入力中もStartを出さない。

|軸|E版のStart/受付管理ST|要求接点|受付保留ST|完了回路|
|---|---:|---:|---:|---:|
|X（2）|288|321|322|323|
|Y（3）|329|362|363|364|
|Z（4）|370|403|404|405|
|コンテナ（5）|411|444|445|446|

既存配列の空きM[2]＝受付済み、M[3]＝保留、M[4]＝運転許可、M[5]＝要求立上りを使用。Start用タイマーに空きTON[3]を使用。

運転許可はAutoMode、Pause[1] OFF、M9999 OFF、RESET OFF、Ready、CommOK、WriteEnable、LayoutConfirmed、ByteOrderConfirmed、AxisApply、MotionPermit、DataValidをANDする。
さらに速度>0、加減速>0、位置決め幅>=0を確認する。
これらの許可値・初期値・実速度/位置/ピッチ値は一切変更していない。未設定なら開始しない。

### 4．箱詰め工程の整合

- 11行目の前工程接点をM14→M16へ変更し、チャック戻工程を待つ。
- 旧36行目のZ MoveDoneを否定接点から正接点へ変更し、上昇完了を確認してから個数判定する。
- 箱内移動選択の直前に、Box_Total_CTが5～80かつ5の倍数かを計算する行を追加。
- X/Yの箱内移動工程全体をその有効判定で制限する。STだけ更新せず古い目標へのAutoを出す経路を防ぐ。
- コンテナ排出完了の立上りでBox_Total_CTを0へ戻し、次箱に備える。
- ローカルBOOL Box_PackCount_Validを1件追加。既存BoxPacking_EndでのBusy解除は保持。

箱詰めは42→43行。追加個数判定が28行目、Xが29行目、Yが30行目となり、以降は旧行番号＋1。新しい動作工程は追加していない。

## 検証

- ZIP CRC異常なし。212内5エントリ変更、その他207エントリは元Dとバイト一致。
- メーカー付属処理：BoxPacking43行、RCON453行、Output316行の解析・モデル変換失敗0。
- 全1361行・1576コイルの接続検査：欠落0、解析/モデル失敗0。
- 箱詰めから出す全Auto要求に対し、全ラダーで同名通常コイル重複なし、受けLD接点ありを確認。
- 既存グローバル変数表のバイト一致を確認。許可フラグの定義・初期値の変更なし。
- 保存済みSTを読み直した条件モデルで、正常、運転不許可、旧PEND ON固定、許可喪失、RESET、完了保持中の次要求の6ケース×4軸＝24ケースを確認。
- Outputの追加OR接点について、自動/手動・一時停止・M9999・センサー・保持条件の1024組合せで、既存回路へ要求ORを追加した形との入力経路同等性を確認。
- 個数の代表範囲-5～90の96値を検査。
- E版が検証済みファイルと一致し、履歴D版が元ファイルのハッシュと一致することを確認。

これらは条件モデルとメーカー付属の読込み・接続検査。**Sysmacの全体再ビルド、STコンパイル、PLCシミュレーター、実機動作の検証ではない。** PLC接続・転送なし。

## 使用前の確認事項

- Sysmacで全体再ビルドし、追加STの構文・変数・FB呼出しが通ることを確認する。
- 4軸の速度、加減速、位置決め幅、各位置、X/Yピッチ、および既存の通信/運転許可を実機仕様に合わせて確認する。
- Start 20ms保持、PEND OFF受付、Start OFF、PEND ON完了の実際の波形と機器設定を照合する。20msは今回の設計値であり、実測確認済み値ではない。
- 受付・完了の異常タイムアウトは今回追加していない。今回の開始解除は、安全停止回路や駆動中の軸停止を保証する処理ではない。
- 要求保留は1件分。複数の異なる次動作を同時にキューへ積む用途ではない。箱詰めの排他工程を保つ必要がある。
- 中断・再開時の入数補正、原点復帰、停止後の復旧手順は既存設備の運用に合わせて確認する。
