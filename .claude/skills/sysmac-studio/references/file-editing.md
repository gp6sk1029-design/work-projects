# .smc2編集

`.smc2`はこの環境ではZIP。暗号化/別形式を同じものとして扱わない。変更したエントリのみ差し替え、未変更バイト・ZipInfo・BOM・改行を保持する。

`.oem`の`Entity type="PouBody"`から節名とIDを取り、対応`.xml`を読む。ラダーは1行1JSON（`CLs`/`VLs`）、変数表は`[SLWD version=1.0]`。拡張子がXMLでも全てをXMLパーサーへ渡さない。

節名はコントローラ/POUをまたいで重複し得る。`inspect`の`key`か一意な候補を使う。

## ラダー

- LD=接点、Not=true=否定、ST=コイル、F=命令、FB=FB、IST.TXT=インラインST、HL/VLs=結線。省略座標は0。
- 列追加時、合流/分岐の縦線をどちらへ移すか判断。自己保持も通る共通否定接点は成立直後に保持を切り得る。
- 新規命令の行はスクリプトの`reindex()`を利用できる。新しいUp/ISTのGUIDは一意にし、既存GUID/IST本文/サイズは不要に変更しない。
- IST追加はOEMのInline登録なども確認。JSON要素の追加だけでアプリ全体の整合は保証されない。

## 番号変更

`map-indices`はVarの固定添字を同時写像で置換する。行範囲指定時はその範囲のみ。前後工程、自己保持、他節参照、通常コイル重複を照合する。

ST固定添字は`include_st=true`で明示対象にするか別途修正。動的添字、HMIアクセス、配列要素コメント/初期値は推測しない。必要な変数表/OEM変更を`replace-part`で明示する。

## 公開と検査

版名・保存先・上書きはユーザー指定を優先。特定顧客のフォルダへ固定しない。`publish`は変更前を一意名で履歴保存。構造/変数変更は`--allow-logic`と候補SHAに一致するnative結果が必要。この指定は新たなユーザー承認を求めるものではない。

候補の検査後に元SHAが変わったら最新を取り込み直す。開いているアプリの古いメモリ内容による再上書きにも注意。

検査の段階を区別する：CRC/差分→同梱読込み/接続→工程条件モデル→アプリ全体ビルド/シミュレーター→実通信/単軸/実機。前段の成功は後段の成功を意味しない。
