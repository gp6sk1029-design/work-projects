# I版を基準にした行間・変数コメント

20261105IのBoxPacking／Destackerでユーザーと整えた表示形式を使う。過去のコメント文をそのまま転用せず、今回の保存済みラダーとI/O割付・全参照を根拠に書く。

## 行間コメント：大・中・小の流れ

- **大工程**：その流れの先頭だけに`#【03 ワーク取出し】`。工程のまとまりを区別し、全行に大見出しを繰り返さない。
- **中工程**：`【取出し先の選択】`、`【A側：取出し・退避完了】`など処理単位を示す。
- **小工程**：`チャック後、Z軸上昇完了を確認`など、動作・成立条件を短く書く。単純な行は1～2行でよい。
- 見出し／動作・条件／軸・I/O／分岐・合流を改行・空行で分ける。1条件1行。長い説明を横一列に詰めない。
- 1行はおおむね全角18～23字（半角36～46桁）以内を目安に自然に折り返す。I版Destackerは最大表示37桁だった。数値は強制切断の規則ではなく、Sysmacで横長にならないための目安。
- 長い変数名は途中で切らず単独行へ。日本語の動作名で十分なら変数名を何度も列挙しない。
- 分岐・合流がある行では**どの行から来て、何を条件に、どの行へ進むか**を書く。単純な隣接工程すべてへ冗長な行先を付けない。
- `合流元：3行の安全位置なし`、`安全位置あり →12行：送り戻し`のように条件と行番号を併記。矢印は工程説明でありJMP命令ではない。
- 行追加・番号変更後は分岐/合流の番号も現版に追従。M配列番号とラダー行番号を混同しない。

## I/O・RCONは番号だけで終わらせない

- `【Y1204】：コンテナ排出戻`
- `【X1003】：コンテナ到着`
- `RCON2_1：段バラシ軸`
- `RCON2_4：箱詰めZ軸`
- `位置設定[1]：安全・排出位置`
- `移動要求：Auto[1]`

RCON2_○○だけでなく**何の軸か**を明記する。入力は「何を検出するか」、出力は「何を動かすか」を短く書く。方向・用途・センサー検出位置を名前だけで推定しない。機械のユーザー確認を優先する。

### 行間コメントの見本

```text
#【03 ワーク取出し】

【取出し先の選択】
ST7の取出し待ちを確認し、A側を優先
Busy成立まで選択を保持

合流元
・14行：コンテナ準備完了
・39行：80個未満で繰返し

A側選択 →16行：A側Busy
B側選択 →17行：B側Busy
```

```text
【初回：安全位置の判定】
RCON2_1：段バラシ軸
位置設定[1]：安全・排出位置

安全位置あり →12行：送り戻しへ合流
安全位置なし →4行：爪戻し
```

この行番号は書式見本。実データに一致させてから使用する。

## 変数コメント：接点を見て役割が分かる長さ

- `Com`は短い役割名。通常は全角8～16字程度を目安とし、状態＋対象が分かる表現にする。必要な意味を削って字数だけに合わせない。
- 工程配列の各要素は`EC`を付ける。`段バラシ：`、`箱詰め：`だけで済ませず、`初回の爪保持`、`コンテナ確認OK`、`送り戻り待ち`など状態や動作を区別する。
- **開始／指令中／完了待ち／確認OK／完了／初回済み**を実際の生成条件で区別。開始しただけのMへ「動作完了」と書かない。
- `Busy`は`初回処理中`、`End`は`1サイクル完了`のように何の状態か示す。異常は`方向・1段目確認異常`など原因を短くする。
- 位置・ピッチは用途と単位を付ける。例：`左SF積みピッチ [mm]`、`目標位置 [mm]`。正負で数値が増減することと実物の上下方向は区別する。
- 配列の位置設定、計算式、HMI表示の説明を整合。実式が基準[3]なら説明[2]を放置しない。基準番号をコメント修正の都合で制御側から変えない。
- 計算・保持・解除の長い説明や前提は行間コメントへ分ける。長い変数コメントで接点表示を縦横に広げない。

| 変数・要素 | 短いコメントの例 |
|---|---|
| `Destacker_Init_Busy` | 初回処理中 |
| `Destacker_End` | 1サイクル完了 |
| `Destacker_M[12]` | 通常サイクル開始 |
| `Destacker_M[15]` | コンテナ確認OK |
| `Destacker_M[26]` | 初回確認済み |
| `Destacker_M[30]` | 1段目 前完了解除 |

## 同期と確認

1. Com／ECは該当グローバル・ローカル・POU外部参照を検索し、表示の不一致を残さない。
2. I/O番号・RCON軸名・設定番号・分岐/合流行番号を実ラダーと照合。
3. コメントだけの依頼では、ラダーの非CMT差分0、変数宣言・型・属性は不変を確認。Com／EC以外へ触れない。
4. 一覧表を求められたら「行番号・コメント」「変数・短いコメント」を分けて提示。長い場合も本文に代表例を載せ、全一覧はファイルへ。
5. 内部本体・外部SMC2・アプリ表示の反映範囲は分けて報告する。閉じた本体への更新手順は[internal-projects.md](internal-projects.md)。
