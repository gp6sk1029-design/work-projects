RCON 2台・11軸 ST実装版／20261019B
対象：3089-2603A_検査箱詰め装置_CORE_SUB_PIP-02F02NX_20261019B.smc2

【最初にお読みください】
指定A版のコピーへ、前回提案した「入力復元・出力変換・許可付きI/O代入」を組み込みました。
原本A版は変更していません。PLC・RCONへの接続、設定変更、転送は行っていません。
Sysmac Studioでの読込み・全体再ビルドは未実施です。実機へそのまま転送しないでください。
独自PCモデルでの試験は、メーカーのコンパイル・シミュレーター・実機試験とは異なります。

今回追加したのは「翻訳係」です。自動運転・位置決めの受付管理・安全停止を完成させたものではありません。
書込み許可をOFFにしても最後の出力は残ります。「書かない」と「停止させる」は違います。

1．どこへ追加したか
Sysmacツリーの OtherDevice_外部機器 → RCON_IAI を開いてください。
元のP_Off→IAI_Mの回路はそのまま残し、その下へインラインSTを6ブロック追加しました。

  RCON1－1 IN読取りと現在値の復元
  RCON1－2 OUT数値変換と制御bit組立
  RCON1－3 許可条件付きの実I/O書込み
  RCON2－1 IN読取りと現在値の復元
  RCON2－2 OUT数値変換と制御bit組立
  RCON2－3 許可条件付きの実I/O書込み

各ブロックには、その処理を行う理由・単位・具体例・注意事項を日本語のコメントで入れました。
STを独立した別プログラムへ置いたものではなく、画像で指定されたラダーセクション内のSTです。
ST6ブロックは上から順番に実行する形式です。既存のタスク登録・周期は変更していません。
元のIAI_M接点でST全体を止める構成ではありません。入力表示と内部計算は実行され、実出力だけ別の許可で保留します。

2．2台の対応
RCON1：Node1、6軸、144Byte/方向、各72ワード。実変数はE001_から始まります。
RCON2：Node5、5軸、112Byte/方向、各56ワード。実変数はE005_から始まり末尾に_1があります。
例：E005_Out_OUT08_2003_09_1。末尾_1なしの古い未割付変数とは区別しています。
実ファイル内のAT=ECAT://node#...と照合しました。物理機構とNode番号の対応は実機側でも確認してください。

両方とも「全軸が直接数値指定・直動軸・固定共通8W・軸No.順に各8W」の設計です。
容量が同じでもポジショナー1、簡易直値、追加占有、軸順変更などがあると配置が変わります。
実機のモード・占有情報を今回読み出して確定したわけではありません。

3．軸番号と通信ワード
                 人が使う番号  実機軸No.  入力/出力のワード番号
  共通領域            ―          ―       00～07
  1軸目              [1]         No.0     08～15
  2軸目              [2]         No.1     16～23
  3軸目              [3]         No.2     24～31
  4軸目              [4]         No.3     32～39
  5軸目              [5]         No.4     40～47
  6軸目：RCON1のみ    [6]         No.5     48～55

RCON2に[6]はありません。受信配列は0～55、送信候補配列は0～47です。
RCON1は受信配列0～71、送信候補配列0～55です。通信容量と今回使う範囲は分けています。
実出力へ書く候補は、共通OUT00と各軸8ワードだけです。合計はRCON1が49、RCON2が41ワードです。
OUT01～07、RCON1のOUT56～71、RCON2のOUT48～55は一切書き換えません。
この余剰領域を「永久に予約」と断定せず、未確認領域として保持しました。

4．グローバル変数とローカル変数の違い
グローバル：他のプログラムや画面からも使う、共通のデータ置き場です。
  既存のRCON1_OUT[1..6]／RCON1_IN[1..6]、RCON2_OUT[1..5]／RCON2_IN[1..5]をそのまま使います。
  4種類39メンバーの既存構造体も変更・複製せず共用しました。
  RxRaw、RxWord、TxWord、TxUInt、許可・判定・診断などを各台28個、計56変数追加しました。

ローカル：OtherDevice_外部機器の中だけで使う、計算の作業用データです。
  ConvAxisIndex：いま何軸目か。ConvBase：その軸の先頭ワード番号。
  ConvDWord：上下ワードの分割・結合用。ConvScaled：単位換算中の小数値。
  ConvPos／ConvBand／ConvSpeed／ConvAccDec／ConvPush等、計12変数を追加しました。
  2台を上から順番に計算するため、作業変数12個は共用できます。指令や受信結果は台別に保持しています。
  複数タスクからこの作業変数を同時に使う設計へ変える場合は再検討が必要です。

VAR_EXTERNAL（外部参照）：このプログラムからグローバル変数を使うための登録です。
  必要な280変数をローカル変数表の外部参照へ登録しました。新たな280個の別データを作ったわけではありません。
  同じ名前でもVARとして別のローカル変数を作ると、グローバルと別物になり誤動作の原因になります。
  追加した実体56個はVAR_GLOBAL、作業変数12個はVAR、参照280個はVAR_EXTERNALです。追加は全て非保持です。
  I/O割付済み256変数には、方向・ワード・意味が分かるコメントも補足しました。名前・型・ATは変更していません。

5．①入力STが行うこと
E始まりの実入力→RxRaw→必要ならバイト交換したRxWord→RCON*_IN[軸番号]へ復元します。
たとえばRCON1_IN[1].ActualPos_mmが1台目1軸目の現在位置です。
位置は2ワードを結合し、負数の符号を復元してから0.01倍してmmへ戻します。
下位2540・上位0なら25.40mm。下位4489・上位1なら700.25mm。
下位62996・上位65535なら-25.40mmです。単純にUINTを足すだけでは負数を正しく読めません。
電流は32bit符号付きmAへ戻します。RCON-PCでは指令電流で、実測トルクを取得した意味ではありません。
現在速度は16bit符号付き値×実機速度単位。AlarmCodeはUINT、状態はStatusの12BOOLへ分解します。

DataValidはメーカーから直接受信するbitではなく、この実装で設けた条件判定です。
通信・割付・バイト順・単位・RUN・軸リンクを確認した場合だけTRUEになります。
DataValidがFALSEでも、位置や状態には仮の復元値が表示されます。値が出たことだけで正しいと判断しないでください。
DataValid=TRUEも安全・運転許可の保証ではありません。

6．②出力STが行うこと
RCON*_OUT[軸番号]へ、人が扱う単位の値を設定すると、送信候補TxWord/TxUIntを作ります。
ここではまだ実I/Oへ書きません。数字の入力と実機への送信を分けています。

学習用の設定例（この代入例は実行コードに追加していません。実機推奨値ではありません）：
  RCON1_OUT[1].TargetPos_mm    := LREAL#25.40;   // 目標位置25.40mm
  RCON1_OUT[1].PositionBand_mm := LREAL#0.10;    // 位置決め幅0.10mm
  RCON1_OUT[1].Speed_mm_s      := LREAL#20.0;    // 速度20mm/s
  RCON1_OUT[1].AccDec_G        := LREAL#0.20;    // 加速・減速とも0.20G
  RCON1_OUT[1].PushLimit_pct   := LREAL#50.0;    // 電流制限50%の換算例

速度単位が0.1mm/s/カウントで、制御bitを全てOFFにした場合の通信値：
  OUT08=2540、OUT09=0       ：位置を0.01mm単位にして上下へ分割
  OUT10=10、OUT11=0        ：幅を0.01mm単位にして上下へ分割
  OUT12=200                 ：20÷0.1
  OUT13=20                  ：0.20×100
  OUT14=127                 ：50×255÷100の小数部を切捨て
  OUT15=0                   ：ControlがすべてOFF
Control.ServoOnだけTRUEならOUT15は論理値16、さらにStartもTRUEなら17です。
バイト交換が必要な構成では、実I/Oへ渡すUINTの数値は上記の論理値とは異なります。
ServoOnやStartを例の数値だけを見てONにしないでください。開始・停止は機械側の手順が必要です。

RCON1_SpeedUnit_mm_s／RCON2_SpeedUnit_mm_sは、実機設定に合わせた1.0または0.1を使います。
今回は実機未確認のため初期値0のままです。0ではEncodeError=1となり、軸出力の更新を保留します。
位置・幅・速度・加減速はTRUNCと±0.5で四捨五入を明示。押付け制限のみ切捨てです。
9999.99mm等の検査値は通信変換上の範囲であり、その機械が動いてよい範囲ではありません。

7．③実出力へ書くための条件（動かすための即席手順ではありません）
全体：WriteEnable、LayoutConfirmed、ByteOrderConfirmed、CommOK。
共通OUT00：上の全体条件に加えてGwApply。
各軸：上の全体条件に加えてAxisApply、EncodeOK、IN.DataValid、MotionPermit。

各確認・許可BOOLは初期FALSEです。このSTから勝手にTRUEにはしません。
LayoutConfirmed：全軸直接数値指定・8W固定・軸順・占有を実機設定と照合した記録。
ByteOrderConfirmed：ゼロ以外の既知位置と既知bitで、ワード順・バイト順を照合した記録。
SwapBytes：必要な場合だけ1ワード内の上下バイトを交換。初期FALSEは「不要を確認済み」ではありません。
CommOK：CPU/ノードの実通信状態を使って別処理で生成。受信値が見えるだけ、TRUE固定では不可。
MotionPermit：ストローク・到達先・速度・加減速・原点・異常・干渉・安全回路などを別処理で検査。
相対移動の場合は、移動量だけでなく現在位置＋移動量の到達先も確認します。

OFFやエラーで更新を止めても、前に書いたStart・ServoOn・BrakeReleaseなどは残り得ます。
停止・非常停止・通信異常時の出力処理は別設計です。特に縦軸のブレーキ解除は落下の危険があります。
原点復帰・リセット・ジョグを位置決めデータ不正時にもどう扱うかも、運転管理側で決定が必要です。
今回、CommOK生成・安全許可・異常停止・自動運転・DSTR受付管理を仮のTRUEで埋めてはいません。

8．開始受付は別のシーケンス
取説の直接数値指定では、データ確定→DSTR ON→PEND OFF確認かつ10ms以上保持→DSTR OFF→PEND再ON確認が必要です。
DSTR OFFまでは指令データを保持し、受付待ち・完了待ちにタイムアウトを設けます。
Startを常時ONにするだけのプログラムではありません。通信変換STにこの運転シーケンスは含めていません。
受信のPositionDoneは今回の指令前からONの場合もあるので、ONだけを拾って完了判定しないでください。

10．診断を見る順番
  EncodeError[軸]：0=変換可能、1=速度単位、2=位置、3=幅、4=速度、5=加減速、6=押付け、7=ジョグ両方向。
  IN[軸].DataValid：入力の前提を満たしているか。
  GwRun／AxisLinked[軸]：ゲートウェイ応答と軸リンク。
  GwWritten／AxisWritten[軸]：そのPLC実行サイクルで実変数へ代入したか。RCON受付の意味ではありません。
  Status.Alarm／AlarmCode：軸異常。共通GwAlarmCodeとは別物です。
